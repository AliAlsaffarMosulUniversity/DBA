# BA-DMS Cloud 3.0 — قسم إدارة الأعمال

نسخة مخففة تعتمد حصريًا على **GitHub + Cloudflare Workers + Google Firebase**. جهاز المستخدم ليس خادمًا، ولا يلزم خادم جامعة أو Python أو Docker. الواجهة وواجهات API في نشر Cloudflare واحد، والهوية في Firebase Authentication والبيانات في Cloud Firestore.

## الميزات المنفذة

- واجهة عربية متجاوبة بملفات التدريسيين، الإضافة والتعديل والبحث والتصدير.
- دخول ببريد وكلمة مرور عبر Firebase مع تأكيد البريد واستعادة كلمة المرور. لا تخزن كلمات المرور في التطبيق.
- أدوار مدير النظام ورئيس القسم والمقرر والتدريسي، وتعطيل الحسابات. أول دخول بغير البريد الإداري يتطلب ملف تدريسي يحتوي البريد المؤكد.
- تبليغات لمستلمين محددين، فتح مستقل عن تأكيد الاطلاع، سجل تأكيدات وتصدير CSV وأرشفة.
- مرفقات على هيئة روابط HTTPS فقط؛ لا رفع ملفات ولا Cloud Storage ولا Google Drive API.
- إدخال الجداول الدراسية والامتحانية بالتواريخ الفعلية والأوقات، صباحًا أو مساءً. فحص تعارض القاعة والشعبة والتدريسي والمراقب، داخل الخطة ومع الخطط المنشورة. المسودة ثم الاعتماد والنشر والأرشفة، ونسخ خطة إلى مسودة جديدة.
- CSV وطباعة المتصفح وحفظ PDF عبر نافذة الطباعة.
- التعديلات تستخدم شروط إصدار Firestore لمنع الكتابة فوق تعديل متزامن؛ جميع الخطط في وثيقة واحدة لضمان عدم نشر خطتين متعارضتين في الوقت نفسه.

## ما أزيل من هذه النسخة

OR-Tools والتوليد التلقائي والتحسين، FastAPI وPostgreSQL وSQLite، Docker والخادم المحلي، ملفات المرفقات المحلية، الترحيلات القديمة، استيراد Excel داخل المتصفح، إدارة الأنصبة والسعات والتجهيزات وعدم التوفر وعلاقات الطلاب المشتركين، سجل تدقيق شامل، تصدير XLSX وPDF من الخادم. لا تدعي هذه النسخة تكافؤها مع المحرك السابق. وثائق النسخة القديمة ليست تعليمات تشغيل هذه النسخة.

الجداول تُدخل وتُراجع بشريًا، وليس لها تكرار تلقائي على الفصل. فحص التعارض يعتمد على الأسماء الموحدة للشعب والقاعات ومعرفات التدريسيين والتاريخ والوقت. اختلاف كتابة اسم القاعة أو الشعبة قد يمنع اكتشاف التعارض؛ استعمل تسمية موحدة. لا تعديل مباشر لجدول منشور: انسخه وعدله ثم أرشف السابق واعتمد البديل.

## حالة التحقق

نجح بناء React/TypeScript و18 اختبار Node تشمل الصلاحيات، فصل الفتح عن التأكيد، الأدوار، تعطيل الحساب، تعارضات ونشر الجداول، توقيع Firebase JWT، وعقد Firestore REST. اختبارات Firestore تستخدم HTTP بديلًا، وليست اختبارًا للخدمة السحابية. لم يُتحقق بعد من نشر Cloudflare أو تسجيل دخول Firebase الفعلي أو استيراد الملفات إليه. لا توجد هنا عبارة نجاح وهمية إذا غابت الإعدادات.

## إعداد Firebase مرة واحدة

المشروع المقصود `ba-dms-mosul`، وقاعدة Firestore الافتراضية موجودة بالفعل في `me-central1`.

1. في Firebase Console: Authentication → Sign-in method، فعّل Email/Password فقط. قد يظهر Authentication تحت Security.
2. Project settings → General → Your apps: أنشئ تطبيق Web إن لم يوجد، وخذ **apiKey** من إعداد التطبيق. هذه قيمة عامة لازمة لـFirebase Authentication، وهي تختلف تمامًا عن مفتاح حساب الخدمة الخاص.
3. احتفظ بقواعد `firebase/firestore.rules` المغلقة. المتصفح لا يقرأ Firestore مباشرة؛ Worker يستخدم IAM ويحمي العمليات حسب الدور. لا تفتح قواعد القاعدة للعامة.
4. ضع ملف اعتماد الخدمة في `.local/firebase-admin.json` محليًا. توجد نسخة محلية خاصة للمشروع على هذا الجهاز فقط؛ لا تُضمّن في الحزمة أو GitHub.
5. ضع `.local/deploy-settings.json` محليًا بهذا الشكل، مع apiKey الفعلي:

```json
{"apiKey":"YOUR_FIREBASE_WEB_API_KEY"}
```

## نشر Cloudflare

لا يلزم دومين مدفوع. يكفي رابط workers.dev. لا تختَر خطة مدفوعة ولا تربط Firebase بـBlaze.

### من GitHub عبر Cloudflare Builds

ارفع هذه النسخة في مجلد `cloud` داخل مستودع DBA. من Cloudflare Workers & Pages → Create application → Import a repository اختر DBA بعد منح Cloudflare الوصول إلى هذا المستودع فقط.

| الحقل | القيمة |
|---|---|
| الاسم | ba-dms-mosul |
| Root directory | cloud |
| Build command | npm install && npm --prefix frontend ci && npm run build && npm test |
| Deploy command | npx wrangler deploy |

أضف متغيرين في إعداد **Worker runtime** (إعدادات Build وحدها لا تكفي):

- `FIREBASE_SERVICE_ACCOUNT`: نوع **Secret**، ومحتواه JSON اعتماد الخدمة كاملًا. لا تضعه في wrangler.jsonc ولا ملفات React ولا متغيرًا يبدأ بـVITE_.
- `FIREBASE_WEB_API_KEY`: apiKey العام من إعداد تطبيق Firebase Web. يمكن وضعه Secret أيضًا؛ يُرجعه `/api/config` للواجهة لأنه إعداد عام.

`FIREBASE_PROJECT_ID` و`ADMIN_EMAIL` مضبوطتان في wrangler.jsonc. أول مستخدم ببريد `ali_alsaffar@uomosul.edu.iq` المؤكد يصبح مديرًا. يجب أن يكون إعداد البريد الإداري تحت سيطرة مالك المشروع. بعد النشر افتح الموقع وأنشئ الحساب بنفسك، وأكّد البريد، ثم سجل الدخول. لا تستخدم كلمة مرور حساب Google؛ اختر كلمة مرور خاصة بهذا التطبيق.

### نشر مرة واحدة من الجهاز

بعد إعداد الملفين الخاصين أعلاه وتثبيت Node.js، انقر `DEPLOY-CLOUD.cmd`. يبني الموقع ويختبره ثم يطلب تسجيل دخول Cloudflare عبر متصفحه الرسمي ويضع الأسرار وينشره. هذه عملية نشر مؤقتة، ويمكن إغلاق الجهاز بعد انتهائها؛ لا تشغل عليه أي خادم. يتطلب اتصال إنترنت عاديًا؛ بيئة Codex الحالية لا تستطيع الوصول إلى npm أو Google مباشرة.

## بيانات القسم

35 ملفًا حقيقيًا جاهزة محليًا في `.local/faculty-profiles.json` خارج Git والحزمة، دون كلمات مرور أو أدوار. بعد مراجعتها، يشغّل مالك المشروع `node scripts/import-profiles.mjs --apply` مرة واحدة من مجلد النسخة. الأداة ترفض وجهة فيها ملفات وتستخدم معرفات ثابتة وشروط إنشاء لمنع الكتابة فوق بيانات قائمة؛ إذا انقطع الاتصال يمكن إعادة الأمر بأمان مع الملف نفسه. دون `--apply` تجري فحصًا محليًا فقط. لا تنقل الحسابات القديمة أو كلمات مرورها. بعد الاستيراد ينشئ كل تدريسي حساب Firebase ببريده ويؤكده. الملفات الناقصة تُضاف من الواجهة.

## الحدود والتكاليف

لا خدمات مدفوعة مطلوبة في التصميم، لكن المجاني له حصص وقد تتوقف الخدمة عند تجاوزها. Workers Free: 100,000 طلب يوميًا و10ms CPU لكل طلب و50 طلبًا خارجيًا لكل تنفيذ؛ لم يقس زمن التنفيذ الفعلي داخل Cloudflare بعد. راقب الاستخدام ولا تعتمدها رسميًا قبل التجربة. حد التطبيق 100 جلسة للخطة، 20 خطة محفوظة إجمالًا بما فيها المؤرشفة، و200 جلسة منشورة إجمالًا، وحجم مخزن الخطط 250,000 محرف. 100 مستلم للتبليغ و6 روابط، وآخر 100 تبليغ في العرض. حد القراءة 2000 وثيقة لكل مجموعة؛ نمو التأكيدات يتطلب إضافة ترقيم صفحات وتنظيف مؤرشف قبل تجاوزه. حد الطلب 180KB. محدد الطلبات تقريبي حسب موقع Cloudflare وليس حدًا عالميًا دقيقًا. جلسة الدخول في الذاكرة فقط وتنتهي عادة خلال ساعة أو عند إعادة تحميل الصفحة. تسجيل الخروج لا يُبطل رمز Firebase المنسوخ فورًا؛ تعطيل الحساب داخل التطبيق يمنع طلباته التالية.

لا نسخ احتياطي شامل أو استعادة تلقائية في هذه النسخة؛ تصدير CSV للملفات والجداول والتأكيدات للمراجعة فقط. يجب ترتيب نسخ آمن قبل الاعتماد على بيانات مهمة. المرفقات الخارجية تخضع لصلاحيات مالك الرابط، ولا يتحقق النظام من محتواها أو صلاحية المستلم عليها. استدعاءات Authentication والتحقق من البريد لها حصص Firebase أيضًا.

المراجع الرسمية: [Cloudflare Static Assets](https://developers.cloudflare.com/workers/static-assets/)، [حدود Workers](https://developers.cloudflare.com/workers/platform/limits/)، [Firestore REST وIAM](https://firebase.google.com/docs/firestore/use-rest-api)، [دخول Firebase بالبريد](https://firebase.google.com/docs/auth/web/password-auth)، [حصص Firestore](https://firebase.google.com/docs/firestore/quotas).

## التطوير والاختبار

```text
npm install
npm --prefix frontend ci
npm test
npm run build
```

إن أردت بيئة تطوير مؤقتة: `npm run dev` مع أسرار اختبار في `.dev.vars` المستبعد من Git. لا ضرورة لذلك لاستخدام النسخة المنشورة. الواجهة لا تحتاج عنوان خادم خارجي؛ جميع `/api/*` على نفس نطاق Worker.
